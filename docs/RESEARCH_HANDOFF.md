# Research Handoff and Reproducibility Notes

This document describes the **actual current implementation** so a report, paper or presentation does not accidentally make claims the code does not support.

## 1. ML dataset

The committed `backend/data/crop_data.csv` currently contains:

- **5,600 rows**
- **56 crop classes**
- **100 generated rows per crop**
- seven model features: N, P, K, temperature, humidity, pH and rainfall
- one target column: crop label

The dataset is generated by `backend/generate_dataset.py`.

### Important

Do **not** describe the current 5,600-row file as a direct 5,600-row Kaggle dataset unless you independently replace or verify it.

The generator creates samples from crop parameter distributions encoded in the project. The current file is best described as a **synthetic/generated dataset based on configured agronomic ranges**.

The generator uses `numpy.random.seed(42)`.

## 2. Model

`backend/model.py` uses:

- `RandomForestClassifier`
- 300 trees
- `max_depth=None`
- `min_samples_split=2`
- `random_state=42`
- `n_jobs=-1`
- stratified 80/20 train/test split
- split `random_state=42`

The stored accuracy is standard classification accuracy on that held-out split.

For stronger academic evaluation, add macro precision, recall, F1, confusion matrix, per-class performance and cross-validation.

## 3. What the classifier directly uses

The Random Forest receives only:

1. nitrogen
2. phosphorus
3. potassium
4. temperature
5. humidity
6. pH
7. rainfall

The API/frontend also accepts organic carbon, electrical conductivity, season, irrigation, previous crop, location, land area and budget.

Do not claim all frontend fields are Random Forest features unless the model is changed accordingly.

## 4. Fit score is not raw model probability

The backend calls `predict_proba()`, then transforms the returned probability into a display-oriented `fit_score`.

The current implementation normalizes candidates relative to the strongest candidate and enforces a minimum displayed score for returned candidates.

Therefore:

- raw Random Forest probability != displayed fit score
- fit score is not calibrated probability
- research evaluation should use model outputs/metrics directly

## 5. Overall recommendation score

```text
overall_score =
    0.45 * fit_score
  + 0.35 * market_score
  + 0.20 * profit_index
```

`profit_index` is derived from fit and market score.

This is an application ranking heuristic, not an independently trained ML target.

## 6. Market data

`backend/market_data.py` contains project-defined assumptions including price scores, demand categories, export scores, costs, yields and prices.

If `DATA_GOV_API_KEY` is configured, the backend can query the data.gov.in AGMARKNET resource and use a recent live modal price for mapped commodities.

Otherwise it falls back to static project values.

A paper should state which mode was used.

## 7. Ten-year mandi archive

`backend/data/mandi_price_history_2016_2026.csv` contains 7,000 monthly rows from Jan 2016 to May 2026.

The current summary records:

```text
official_api_seeded_crops: 0
```

The archive builder generates the time series from project market baselines using deterministic trend/seasonality/volatility logic.

It should **not** be represented as 7,000 directly observed historical AGMARKNET records.

If a publication requires official historical mandi observations, source a real historical dataset separately and document provenance.

## 8. Weather

The backend uses Open-Meteo for geocoding and as the primary forecast provider. If the forecast call is rate-limited or unavailable, it falls back to MET Norway Locationforecast.

The displayed rainfall value is an **annualized estimate derived from a short forecast window**, then clamped to the app's supported range. It is not a measured annual rainfall total.

For research involving rainfall, use a documented historical climatology dataset if required by the methodology.

## 9. Soil report extraction

PDF reports:
- text extraction via `pdfplumber`

Image reports:
- OCR via Tesseract through `pytesseract`

Extracted text is matched using regex patterns and range checks.

This is OCR + rule-based parsing, not an LLM document-understanding system.

## 10. Profit / ROI outputs

Revenue, profit and ROI are calculated from project-defined cost/yield assumptions, static or live price, and user land area.

These are scenario estimates, not guaranteed financial forecasts.

## 11. Recommended reproducibility record

For every academic result, record:

- Git commit SHA
- Python/library versions
- immutable dataset copy or checksum
- dataset rows/classes
- split and seed
- model hyperparameters
- evaluation metric definitions
- live API configuration
- exact demo inputs
